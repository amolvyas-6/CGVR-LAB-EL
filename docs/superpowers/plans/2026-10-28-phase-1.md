# Phase 1 implementation plan

Approved scope: the functional scaffold in `../specs/2026-10-28-transfer-planner-design.md`. No mission mathematics or immersive interactions in this phase.

## Design pass

- Palette: instrument white `#f5f7fa`, panel white `#ffffff`, ink `#243348`, muted steel `#5d6d82`, engineering blue `#245da8`, preview slate `#dce4ed`.
- Type: local system sans for controls and headings; local system monospace only for measured values. No remote fonts or assets.
- Layout: left-aligned instrument workspace, wide material-preview viewport, narrow setup/status column, and a compact unavailable-results area. Stack on mobile. Borders separate functional regions; no decorative card grid, space-game background, glow or score-like metrics.
- The memorable element is the textured, inspectable body itself. All displayed bodies are static asset previews, not ephemeris positions. Scientific output stays unavailable.
- Review against brief: this is an instrument workspace, not a landing page or cockpit. Avoid invented launch dates, fake plots, and arbitrary orbital arrangements. Preview controls affect only the material preview.

## Task A — pure helpers (Luna high)

Own `src/physics/*`, `src/app/state.js`, and helper/state tests. Implement frozen constants, finite unit conversions, strict UTC date-only parsing/formatting, small vector operations on plain three-element arrays, and immutable snapshot/update/subscription state. No three.js imports. Tests cover nominal and invalid inputs, UTC rollover rejection, and immutable state/unsubscribe semantics.

Shared state interface: `createState(initialState)` returns `getSnapshot()`, `update(patch)`, and `subscribe(listener)` (returns unsubscribe). Snapshot objects are deeply immutable; update uses a shallow patch and notifies only after a valid replacement. Initial/update values are plain data, not mutable Date/Map/Set instances.

## Task B — runnable instrument shell (Luna high)

Own root scaffold/config, `src/main.js`, rendering/preview modules, stylesheet, telemetry helper, asset manifest, and README. Pin three.js 0.186.1, Vite 8.3.5, Vitest 5.0.5, stats.js 0.17.0; document their Node requirement. Build with a relative Vite base for static subpath hosting. Add only these dependencies for now.

Use a static inspectable body with OrbitControls and truthful preview controls. Import supplied textures as build-managed URLs; do not copy/edit assets or load the GLB. Texture 6 is the Saturn ring stripe, not a planet surface; defer the ring mesh if unnecessary. Keep all mission results unavailable. Use an XR-ready camera rig and `setAnimationLoop`, but no XR entry/controllers yet. Handle WebGL/texture failures visibly, resize, teardown/HMR, and resource disposal. Use Task A's state contract rather than duplicating it.

## Task C — supervisor integration and independent review

Install pinned dependencies and retain lockfile. Run unit tests and production build; inspect dependency advisories. Check browser rendering, interaction, resizing, missing-texture fallback, static subpath asset paths, and resource ownership using a temporary browser-test harness when available. A fresh Luna-high reviewer inspects the implementation. Supervisor corrects defects and reruns affected checks.

## Completion criteria

The desktop scaffold is usable with real textures, every unavailable scientific output is explicit, helpers are tested, and no Phase 2/3 production implementation has slipped in. Document commands, scope, verification results, and any remaining browser/emulator limitations. Do not initialize Git or change supplied context/assets.
