# Phase 2 implementation plan

Scope is already approved in the three-phase design. Implement a validated numerical pipeline and the real-data desktop planner; XR remains Phase 3. The unavailable planning skill is replaced by this explicit plan.

## Implementation decisions

- Use pinned `astronomy-engine` 2.1.19 and desktop debug `lil-gui` 0.21.0 alongside the existing pinned dependencies.
- Astronomy Engine documents `HelioState` in EQJ with AU/AU-day units. Apply its fixed `Rotation_EQJ_ECL()` through `RotateState` at the boundary, then convert to km/km/s. All numerical states use heliocentric J2000 mean ecliptic axes, with prograde normal `[0,0,1]`. This is one consistent fixed orientation, not date-varying ecliptic coordinates. Sun-relative acceleration is neglected by the two-body transfer approximation.
- Date inputs are UTC; public ephemeris calls accept valid Date objects. Store grid epochs as Unix milliseconds, never pass those numbers directly to Astronomy Engine (which interprets numbers as J2000 days).
- Start Mars with departure inputs 2026-07-01 through 2027-03-01 and TOF 100–400 days; these are search bounds, not a precomputed claim. Venus and Jupiter get suitable labelled TOF presets when selected. Default resolution 60×60, limited to a modest maximum to prevent accidental huge grids.
- Cost objective is `v∞ departure + v∞ arrival` (km/s), labelled a transfer-cost proxy. Optional proxy/C3 budgets constrain feasibility but do not change the objective. Search both unconstrained and feasible discrete-grid minima.
- Failed physical solves return invalid records with NaN vectors/costs, not uncaught errors. Invalid UI/configuration inputs are validated before computing.
- Keep numerical grids/results outside the immutable UI metadata store. No worker unless a measured hitch requires one; if needed, document the measurement and preserve the same numerical contracts.

## Shared module contracts

All numeric modules live under `src/physics/` and do not import three.js.

- `ephemeris.js`: `getPlanetState(body, date) -> {r, v}` and `getPlanetPosition(body, date) -> [x,y,z]`, plus frame metadata. Support solar-system planet names and Sun; valid Date inputs only. Use documented fixed ECL rotation.
- `stumpff.js`: `stumpff(z) -> {C,S}`, stable near zero.
- `lambert.js`: `solveLambert(r1,r2,tofSeconds,{mu,prograde,referenceNormal}={}) -> {valid,v1,v2,transferAngle,z,iterations,reason}`. Default solar mu and ECL prograde normal. Bracket the zero-revolution universal-variable branch below `4π²`; mask exactly collinear/180° inputs, do not secretly nudge them.
- `propagate.js`: `propagateState(r0,v0,seconds,{mu}={}) -> {valid,r,v,reason}`; `sampleTrajectory(r0,v0,tofSeconds,count=128,{mu}={}) -> {valid,points,timesSeconds,reason}`. Independent universal f/g propagation, not straight-line interpolation.
- `transfer.js`: `computeTransfer({target,departureMs,tofDays}, optionalDependencies) -> {valid,target,departureMs,arrivalMs,tofDays,tofSeconds,r1,r2,v1,v2,vInfDeparture,vInfArrival,c3,cost,transferAngle,reason}`; use Earth departure. Optional dependencies support meaningful grid failure tests.
- `porkchop.js`: `generatePorkchop({target,departureStartMs,departureEndMs,tofMinDays,tofMaxDays,departureCount,tofCount}, optionalDependencies) -> grid` with `costs` and `c3` Float32Arrays, `departureEpochs` and `tofDays` Float64Arrays, config/count metadata and solve statistics. Layout is `index = j*departureCount+i`; x=departure, y=TOF, low TOF at bottom. `getGridCell(grid,i,j)` yields cell input/cost metadata; `findGridMinimum(grid,budget={type:'none',limit:0})` yields a cell or null; `isCellFeasible(cell,budget)` shares the exact CPU/shader budget meaning. Budget types: `none`, `cost`, `c3`.
- `src/app/plotPicking.js`: pure clamp/UV-to-cell mapping, shared desktop/XR semantics; unit tests at all corners. Its final exported signature is documented by the renderer agent before UI integration.

## Task sequence / ownership

1. **Parallel numerical foundation (Luna high):** Agent A owns Stumpff/Lambert/propagation and their tests. Agent B owns ephemeris and tests, plus numerical-method/reference documentation. Neither edits shared Phase 1 helpers or package files.
2. **Numerical gate:** supervisor runs all tests, checks textbook/near-Hohmann propagation and invariant values. Fix findings before connecting visualizations.
3. **Transfer/grid (Luna high):** own transfer/porkchop and their tests. Measure default-grid runtime and record real minimum values. Handle invalid cells, budget types, boundary indices, empty feasible set.
4. **Desktop rendering (Luna high):** own `scene/orrery.js`, `scene/trajectory.js`, `scene/porkchop.js`, GLSL and pure plot-picking tests. One renderer/camera rig; use viewport/scissor for plot and orrery if two views share the renderer. Use real ephemeris and propagated arc only after the numerical gate; reuse these modules in XR later.
5. **Desktop integration (Luna high):** own main/view/index/styles/README. Use the renderer contracts, truthful statuses and real outputs. Existing asset-preview source is not blindly deleted; it becomes unused historical scaffolding. Keep shared pure helpers intact.
6. **Independent review and supervisor verification:** unit/build/audit checks; browser visual/interaction/resizing/error checks; numerical boundary/invariant checks; static-subpath assets and no external runtime APIs. Record actual findings and limitations.

## Engineering visual plan

Retain instrument-white `#f5f7fa`, white `#ffffff`, ink `#243348`, steel `#5d6d82`, and blue `#245da8`. Use muted blue-to-amber scientific cost colours with readable unit-labelled legend, not a decorative neon cockpit. Local system sans; monospace only for numeric results. Left-align labels and result tables. No arbitrary metric tiles, numbered decorative sections, score-like labels, or remote assets.

```text
Title / computation status
Search parameters / compute      Selected transfer results
Orrery with date/scale            Porkchop with axes, legend and picking
Time slider / play / reset        Unconstrained and feasible grid minima
Measured telemetry / physical assumptions
```

Review against the brief: mission inputs and plot are the working instrument, not marketing chrome. Costs must remain inspectable when above-budget (visually masked/dimmed, explicitly infeasible). Invalid cells clear the trajectory, never retain an old transfer under a new selection. Scene time is selected departure plus scrub fraction times TOF; planet and spacecraft positions share it. Auto-play starts only on a user's action and pauses on selection/input changes.

## Acceptance

- Textbook Lambert example; analytic Hohmann reference and near-180° solver cases; propagation endpoint, energy/angular momentum, short/long prograde direction and failure cases pass documented tolerances.
- Ephemeris units/frame/Sun-relative state and finite-difference velocity checks pass.
- Default Mars grid has finite real values and a plausible low-cost island. Document comparison limitations: the Tudat reference is a different window/axis convention, not quantitative validation for 2026.
- Independent same-window plausibility reference: NASA/TM-2010-216764, Table 2, https://ntrs.nasa.gov/citations/20100037210 (fulltext fetched during development). Its no-deep-space-maneuver rows include 2026-11-14→2027-08-09 Type I (C3 11.11 km²/s², arrival v∞ 2.915 km/s) and 2026-10-31→2027-08-19 Type II (C3 9.144, arrival v∞ 2.729). Compare the model at these fixed dates with a documented non-exact tolerance; do not tune constants or force the grid optimum to a type-I TOF. The handbook uses different high-fidelity ephemerides and minimizes C3 rather than our cost proxy.
- Proxy and C3 budgets, infeasible set, grid picking corners, selected outputs and optimum snap agree.
- Real textured orrery, transfer arc/spacecraft, shader colormap/contours, DataTexture, and desktop pointer/keyboard picking work without XR entry.
- Recompute only relevant grid inputs; budget, hover, selection and playback do not rebuild the grid. Teardown disposes all added resources; WebGL/texture failures stay visible.
- Scientific texture values are not colour data: use NoColorSpace, nearest sampling and no mipmaps. Keep NaN in the CPU arrays but upload a finite invalid sentinel or a separate validity channel so masking never depends on GPU NaN behavior. WebGL2 single-channel float sampling with nearest filtering does not require float render-target support; provide/test an RGBA-float path if the selected upload format needs a fallback.
- Unit tests, production build and desktop/browser checks pass; emulator VR testing is explicitly deferred to Phase 3.
