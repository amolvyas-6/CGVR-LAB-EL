## Shared interfaces (do not guess across agents)

### Worker + mission action agent

Own `src/workers/porkchop.worker.js`, `src/app/gridService.js`, `src/app/missionActions.js`, and associated tests. Do not edit main, physics, render or XR files.

`createGridService({workerFactory}={}) -> {compute(config):Promise<grid>, cancel(), destroy()}`. Default factory `new Worker(new URL('../workers/porkchop.worker.js', import.meta.url), {type:'module'})`; worker accepts `{id,config}`, posts `{id,grid}` with transferable costs/c3/axis buffers or `{id,error}`. Latest compute cancels prior promise with `AbortError`, terminates stale worker and lazily starts a fresh one. Error handling clears pending state and permits retry. No synchronous browser fallback.

`applyMissionAction(inputs, budgetInput, action) -> {inputs,budgetInput,missionChanged,budgetChanged,computeRequested}` pure immutable strings. `inputs` shape DEFAULT_MISSION_INPUTS (from app/planner.js); `budgetInput={type:'none'|'cost'|'c3',limit:string}`. Actions `{type:'target',target}`, `{type:'step',field:'departureStart'|'departureEnd'|'tofMinDays'|'tofMaxDays'|'resolution',delta:number}`, `{type:'budgetType',value}`, `{type:'budgetStep',delta:number}`, `{type:'compute'}`. Date delta is days; TOF/resolution numeric delta. Reject unsupported/nonfinite action, do not modify originals. Clamp/safeguard ranges (departure start<end, positive min<max, resolution2..120) with at least 1 day gap. Target presets from tested app/planner. Budget mode change choose sensible threshold (cost6, c315) unless remembered same-unit limit; never reinterpret cost limit as C3. Budget step clamp>=0. Tests real UTC boundaries/leap/day rollover + invariant preservation.

### XR controller agent

Own `src/xr/controllers.js`, `src/xr/input.js`, input/controller tests, `docs/phase-3-controller-contract.md`. Local profile assets supplied by supervisor under `public/xr-profiles/`; no package/dependency modifications or scene/main edits.

`createXRControllers({renderer,rig,hitTest,onHover,onActivate,onScrub,onShortcut,onProfile}) -> {update(nowMs,deltaSeconds),setActive(bool),destroy(),getDiagnostics()}`. `hitTest(raycaster)` returns reusable `{object,point,uv,kind:'plot'|'action'|'time',i?,j?,action?,progress?}` or null; scene agent owns this, never do physics in controllers. onHover(hit|null), onActivate(hit) dispatches trigger selection, onScrub(deltaPercentage) dt-based stick horizontal rate (~25%/s), onShortcut('nextTarget'|'snap') on rising edge of confirmed profile buttons. onProfile receives serializable active sources/profile mapping/instructions. Trigger uses selectstart/selectevents once (not double gamepad dispatch). Unknown controllers retain rays/trigger buttons, no guessed optional shortcuts. Connected/disconnected grip/model/ray lifecycle and runtime standard mappings must be checked. All tracked pointers can activate; choose one deterministic hovered pointer (right preferred then available left), avoid per-frame toggling two independent hover states. Aim ray -Z of controller matrixWorld, reuse raycaster/intersection vector/matrices/reticle, check pose valid/visible, cap dt after focus loss. `getDiagnostics()` exposes current mappings and connection state only (no mutable Three objects).

Use XRControllerModelFactory setPath local `${import.meta.env.BASE_URL}xr-profiles`, guarded loader catches missing model and keeps procedural grip; dispose factory caches/resources, disconnect late loads on teardown. No remote profile URLs. Pure input helpers named/documented by agent and thoroughly tested: deadzone, standard/profile mappings, edge transitions, no invalid gamepad surprises.

### Scene/panel agent

Own updates to `src/scene/plannerScene.js`, `orrery.js`, `porkchop.js`, plus new `src/xr/workbench.js` / text panel helpers, layout tests and `docs/phase-3-scene-contract.md`. Do not edit main/view/input/controller/worker/physics/package.

Extend returned `{xrScene,xrCamera,xrRig,setImmersive(bool),updateXR(deltaSeconds,nowMs),setXRState(snapshot),getXRDiagnostics()}`. `renderer.xr.enabled=true`, foveation1, local-floor normally. `render()` chooses XR scene+camera once if isPresenting, no DOM size/scissor render in XR; desktop branch unchanged except disabled controls while XR. Scene factory owns `createXRControllers(...)` connection using above planned API; import may not exist until peer finishes but contract is fixed. `setImmersive(true/false)` reparent shared orrery content and plot plane to workbench/restores original parents/transforms, preserve cameras/controllers independent of content, do not put orrery camera rig into workbench. May extract content Group in orrery and expose plot.mesh/getCellAtUV, preserving current desktop raycast semantics. Avoid parenting Scene as Group. Uniform scale metres/AU around0.3 Mars and explicit fit Jup. In-world panel can read the same plot grid by wrapper/current variable, no duplicate DataTexture.

`setXRState(snapshot)` holds plain metadata supplied main, repaint canvas only changes/throttled time/perf, never read DOM. Snapshot `{inputs,budgetInput,budgetValid,status,hasGrid,computing,selection,hoverSummary,missionDate,progress,playing,canSnap,canPlay,minimumSummary,assetStatus,scaleExaggerated,telemetry}`; selection is existing formatted selectedOutput or null; inputs strings. In-world controls emit same mission actions above plus `{type:'snap'|'play'|'reset'|'exit'|'scale'|'radii'|'nextTarget'}`, `{type:'scrub',progress}`. Scene/panel agent owns action->hit entries/buttons enable conditions/UV/axes labels/legend from own actual grid/colorRange. Include selected results, minimum summary and short scale/model disclosures. onHover drives existing onHover plot callback (indices|null), scene updates shader+reticle/actions visuals; onActivate plot passes onSelect indices, action passes onXRAction, time passes scrub. Stick onScrub emits `{type:'scrubDelta',delta}` for main to bound. onProfile stores instructions in-world.

`getXRDiagnostics()` plain object for testing/report: session flag, current scale, controller mappings, scene counts if useful, and labelled control/plot world positions or a helper? Prefer expose via `?debugXR=1` main read-only global diagnostic function, not always global mutable app. Scene diagnostics can include plot world corner coordinates + action world centers (arrays) to target emulator pose without private scene hacking. Render tests actually pick rays, not invoking actions directly as acceptance.
